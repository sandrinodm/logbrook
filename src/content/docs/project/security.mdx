## Report a vulnerability

Use GitHub private vulnerability reporting. In the repository, open **Security**, select **Advisories**, then choose **Report a vulnerability**. The report is shared privately with the maintainers.

If that button is unavailable, open an issue asking the maintainers to enable private reporting. Don't put vulnerability details, exploit code, credentials or sensitive logs in that public issue.

In the private report, include:

- The affected version or commit and your deployment configuration.
- Steps to reproduce, preferably with synthetic data and a minimal proof of concept.
- The expected security boundary and how it can be bypassed.
- The impact and any known mitigation.

Don't test against installations you don't own or have permission to assess. Use the private advisory to coordinate a fix and disclosure with the maintainers.

## Supported versions

Logbrook is pre-release software (version 0.2.0). Include the exact commit in reports about unreleased builds. Fixes are not backported to older development snapshots.

## Security-relevant defaults

### Authentication and roles

- **Every data route needs a bearer token.** Search, count, facets, histogram, tail, ingestion, index listing and `/metrics` all require an `Authorization: Bearer` credential. `/health`, `/ready` and `/openapi.json` are public.
- **Three separate roles.** Startup rejects a configuration that reuses one token across the ingest, read and admin roles. Tokens are 16 to 512 visible ASCII characters without whitespace, and example `replace-with-` values are rejected.
- **Admin can't read logs.** Admin tokens manage indexes, including deletion, and can't read or ingest events.
- **Scopes.** Read tokens can be limited to sources, and ingest and read tokens to indexes. `/metrics` requires an unrestricted read token.
- **The server needs credentials to start:** at least one ingest token and one read token.

See [Credentials and roles](/configure/credentials/).

### Network

Logbrook serves plain HTTP and binds to `127.0.0.1:3100` by default. For remote access, put a TLS-terminating reverse proxy in front of it and don't publish the port directly. Responses carry security headers (`x-content-type-options: nosniff`, `x-frame-options: DENY` and a restrictive `content-security-policy`).

The Fluent Forward listener is off until a configuration enables it. A `trusted_local` listener with `trusted_network = true` has no authentication and accepts any peer that can reach it, unless `allow_peers` limits the peer addresses. Use authenticated listeners across trust boundaries. See [Forward listener](/configure/forward-listener/).

### Container

The image is built on a digest-pinned Distroless base with no shell or package manager, runs as UID `10001`, and is meant to run with a read-only root file system, all capabilities dropped and `no-new-privileges`. See [Run in production](/operate/production/).

### Data

Treat application logs and database backups as sensitive data. Keep management credentials separate from ingestion and read credentials, and scope producer and reader tokens to the indexes and sources they need.

Parquet archives written with promoted string attributes carry SHA-256 digests checked at startup and around reads. The digests catch accidental changes, not someone who can also rewrite the database and its manifest.
