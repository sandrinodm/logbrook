Logbrook authenticates every request with a bearer token. There are three roles, and each token belongs to exactly one. This page shows how to configure the tokens, what each role can do, how clients send them, and how to generate and rotate them.

## The three roles

| Role | Configured in | Can do |
| --- | --- | --- |
| Ingestion | `[ingest_tokens]` | Send events. Create an index by writing to it or with `PUT /indexes/{index}`. |
| Read | `[read_tokens]` | Search, count, facets, histograms, live tail and listing indexes. Scrape `/metrics` when unrestricted. |
| Admin (optional) | `admin_tokens` | List, inspect, create and delete indexes. Cannot read or write events, and cannot scrape metrics. |

`/health` and `/ready` are public and reveal no log data.

### Ingestion tokens set the source

Each ingestion token maps to a source name. Logbrook stamps that source on every event the token writes, and the payload cannot change it. Use one token per producer, deployment or team, so you can later read or filter by where logs came from. See [indexes, services and sources](/concepts/indexes-services-sources/).

### Read tokens can be scoped

A read token lists the sources it may read. An empty list means every source. You can also restrict a read token to specific indexes with `[read_index_scopes]`. A request has to satisfy both limits.

- A request that names a source outside the token's list gets `403`.
- A request to an index outside the token's scope gets `403`.
- A token scoped to sources gets only the index name from `GET /indexes/{index}`, not size details.
- `/metrics` needs a read token with no source scope and no index scope.

Ingestion tokens can likewise be limited to indexes with `[ingest_index_scopes]`. Their source is always fixed.

### Admin tokens manage indexes, not events

An admin token can call the index management endpoints. It cannot search, tail or ingest. Deleting an index requires an admin token. Read and ingestion tokens get `403`, and unknown tokens get `401`.

Admin tokens are optional. Without one, you cannot delete indexes over the API. The `default` index and indexes declared in the configuration cannot be deleted even with an admin token.

## Configure tokens

<Tabs syncKey="config">
<TabItem label="TOML file">

```toml title="logbrook.toml"
admin_tokens = ["your-admin-token"]

[ingest_tokens]
"your-ingest-token" = "checkout-prod"

[read_tokens]
"your-read-token" = []
"your-checkout-reader" = ["checkout-prod"]

# Optional index limits.
[ingest_index_scopes]
"your-ingest-token" = ["payments"]

[read_index_scopes]
"your-checkout-reader" = ["payments"]
```

</TabItem>
<TabItem label="Environment">

```sh
export LOGBROOK_INGEST_TOKEN="$(openssl rand -hex 32)"
export LOGBROOK_SOURCE=checkout-prod
export LOGBROOK_READ_TOKEN="$(openssl rand -hex 32)"
export LOGBROOK_ADMIN_TOKEN="$(openssl rand -hex 32)"
```

</TabItem>
</Tabs>

### Rules every token follows

- 16 to 512 visible ASCII characters, with no whitespace.
- It cannot start with `replace-with-`, the prefix of the example file's placeholders.
- No token can appear in more than one role. Ingestion, read and admin values must all differ.
- Source names have 1 to 128 ASCII letters, digits, hyphens, underscores or periods.
- You need at least one ingestion token and one read token to start.

Index scope tables may only name tokens that exist in the matching token table.

### How environment variables combine with the file

| Variable | Effect |
| --- | --- |
| `LOGBROOK_INGEST_TOKEN` | Replaces every ingestion token from the file. Its source is `LOGBROOK_SOURCE`, or `default` when unset. |
| `LOGBROOK_ADMIN_TOKEN` | Replaces the `admin_tokens` list with one token. |
| `LOGBROOK_READ_TOKEN` | Adds one read token. It does not remove the others. |
| `LOGBROOK_READ_SOURCES` | Comma-separated sources for the env read token. Empty grants all sources. |

If the file already defines read tokens, you must also set `LOGBROOK_READ_SOURCES` when you add `LOGBROOK_READ_TOKEN`, unless that exact token is already in the file. Otherwise startup fails. With no read tokens in the file, the env read token can read every source.

<Aside type="caution" title="Environment tokens can orphan index scopes">
`LOGBROOK_INGEST_TOKEN` replaces the whole ingestion table. If `[ingest_index_scopes]` names a token that was displaced, validation fails with `index scope refers to an unconfigured token`. Update or remove those scopes.
</Aside>

## Send a token

Clients send the token in the `Authorization` header with the `Bearer` scheme.

```sh
curl -sS "$LOGBROOK_URL/indexes/payments/logs/ingest" \
  -H "Authorization: Bearer $LOGBROOK_INGEST_TOKEN" \
  -H "Content-Type: application/json" \
  -d '[{"time":1767225600000,"level":30,"msg":"hello"}]'
```

A missing or malformed header returns `401` with `Bearer token required`. An unknown token, or a token of the wrong role, returns `401`. A valid token outside its source or index scope returns `403`, and so does index deletion with a read or ingestion token.

The CLI reads the token from `--token`, then `LOGBROOK_TOKEN`, then a role-specific variable.

| Command | Variables tried, in order |
| --- | --- |
| `logbrook query`, `logbrook count` | `LOGBROOK_READ_TOKEN` |
| `logbrook indexes list`, `show` | `LOGBROOK_ADMIN_TOKEN`, `LOGBROOK_READ_TOKEN` |
| `logbrook indexes create` | `LOGBROOK_ADMIN_TOKEN`, `LOGBROOK_INGEST_TOKEN` |
| `logbrook indexes delete` | `LOGBROOK_ADMIN_TOKEN` |

Prefer environment variables over `--token`, which lands in shell history. See the [CLI reference](/reference/cli/).

## Generate strong tokens

Generate tokens from a cryptographic random source. A 32-byte value as hex gives 64 characters, well inside the allowed range.

```sh
openssl rand -hex 32
```

Generate a different value for each role and each producer. Store them in a secret manager or an environment file with restricted permissions, not in Git. The repository ignores `*.local.toml` for this reason.

When Logbrook fails to parse the configuration, it reports only the line and column, so credentials in the file are not echoed in the error.

## Rotate a token

Logbrook has no hot reload and no token expiry. A change takes effect after a restart. To rotate without dropping producers, run an overlap:

<Steps>
<Step title="Add the new token">

Add a second entry next to the old one in the same table, with the same source or scope. Use the TOML file for this, since `LOGBROOK_INGEST_TOKEN` replaces the whole ingestion table.

</Step>
<Step title="Validate and restart">

```sh
logbrook --config logbrook.toml check-config
```

Restart the server so it loads both tokens.

</Step>
<Step title="Move clients to the new token">

Update producers and readers and confirm they authenticate.

</Step>
<Step title="Remove the old token">

Delete the old entry, validate again and restart. Remove the old token's entries from the index scope tables too.

</Step>
</Steps>

The restart is brief but real, so schedule it as you would any restart. See [run in production](/operate/production/).
