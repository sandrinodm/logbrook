This page shows how to take a consistent backup of a Logbrook data directory, restore it, and upgrade to a new release without losing the ability to roll back.

## What a backup contains

Each index lives in its own directory under the data root:

<FileTree>
- data/
  - indexes/
    - default/
      - events.duckdb
      - events.duckdb.wal
      - archives/ Parquet files
      - temp/
    - payments/
  - .index-trash/ deleted indexes, not a backup
</FileTree>

A backup needs both the DuckDB files and the Parquet archives. Neither holds all retained data alone. Archive paths are stored relative to the data root, so a complete data directory can be moved to a new location.

<Aside type="caution" title="Do not copy a live data directory">
A plain recursive copy of a running server's data directory is not a consistent backup. Stop the service first and wait for it to exit cleanly.
</Aside>

## Back up

<Steps>
<Step title="Stop the service">
Wait for a clean exit. Logbrook cancels maintenance, drains readers and checkpoints the writer on shutdown. Stop producers first if you want them to buffer instead of fail.

```sh
docker compose stop logbrook
```
</Step>
<Step title="Copy the entire data directory">
Copy everything, including any WAL file and all archive files, as one backup. For a container volume, copy the whole volume with a temporary utility container. This example assumes a Compose project whose volume is named `logbrook_logs`; check `docker volume ls` for yours.

```sh
mkdir -p backups
docker run --rm \
  -v logbrook_logs:/data:ro \
  -v "$PWD/backups:/backup" \
  alpine tar -C /data -czf /backup/logbrook-data.tar.gz .
```
</Step>
<Step title="Start the service again">
```sh
docker compose start logbrook
```
</Step>
</Steps>

Treat backups as sensitive data: they contain your application logs.

## Restore

<Steps>
<Step title="Restore into a different empty directory or volume">
Do not overwrite a directory that a running server uses.

```sh
docker volume create logbrook_restore
docker run --rm \
  -v logbrook_restore:/data \
  -v "$PWD/backups:/backup:ro" \
  alpine tar -C /data -xzf /backup/logbrook-data.tar.gz
```
</Step>
<Step title="Fix ownership">
The files must be owned by the service user, UID and GID `10001`.

```sh
docker run --rm -v logbrook_restore:/data alpine chown -R 10001:10001 /data
```
</Step>
<Step title="Start one process on it">
Point a single Logbrook process at the restored data.
</Step>
<Step title="Verify before switching producers">
Check event counts and a few complete events, for example with the CLI:

```sh
docker compose exec logbrook logbrook indexes list
docker compose exec logbrook logbrook query default --since 1h --limit 5
```
</Step>
</Steps>

## Upgrade

At startup Logbrook checks schema versions and runs migrations inside a transaction.

- The hot-table schema is versioned. The SQL for the older steps lives in the repository's `migrations/` directory (`001_initial.sql`, `002_archive_metadata.sql`); the newest step, version 4, is applied when you turn on [promoted string attributes](/operate/archives-and-migration/#promoted-string-attributes).
- An index without promoted string attributes stays on schema version 3. Turning them on upgrades that index to version 4.
- Older archive metadata is migrated before the server starts serving.
- Startup rejects a database whose schema is newer than the binary supports. A binary that only knows version 3 refuses a version 4 index.
- **There are no downgrade migrations.**

To upgrade safely:

<Steps>
<Step title="Back up">
Take a complete offline backup as above.
</Step>
<Step title="Try the new release on a copy">
Restore the backup into a new directory and start the new version on it. Check counts and sample events.
</Step>
<Step title="Upgrade for real">
Stop the service, switch the image tag, and start it again. Pin the tag; see [Releases and container images](/project/releases/).
</Step>
</Steps>

To roll back, restore the pre-upgrade backup together with the previous binary or image. Do not run the previous binary on data the new version already migrated.

<Aside type="note" title="Pre-release software">
Logbrook is at version 0.1.0 and its APIs and storage formats may change before a stable release. Read the release notes before each upgrade.
</Aside>
